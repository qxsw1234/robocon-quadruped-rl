### 关键技术调研结论
| 问题 | 结论 |
|---|---|
| Isaac Gym Preview 4 是否支持 RTX 40 系（sm_89）？ | 支持（PhysX 内核编到 SM_80，40 系靠二进制向前兼容运行） |
| 官方 README 的 torch 1.10+cu113 能用吗？ | **不能**，40 系上报 nvrtc 错误，必须换 torch 2.3.x+cu121 |
| Python 版本？ | Isaac Gym 二进制只支持 Python ≤3.8 ABI → 必须用 python 3.8 |
| 驱动 570+/580 兼容性？ | 有 Vulkan/coredump 报告 → 用 `--headless` 规避；不行则切 mjlab |
| 8GB 显存 | `--num_envs` 降到 1024~2048（默认 4096 需 ~12GB） |

### mjlab 自定义机器人踩坑记录（A1 接入）
1. **MuJoCo Warp margin 冲突**：menagerie A1 的 `<geom margin="0.001"/>` 与 warp MULTICCD 不兼容 → 报 `NotImplementedError` → 改 margin=0
2. **缺少 IMU 传感器**：`robot/imu_lin_vel` 找不到 → A1 的 menagerie XML 没有 sensor 定义 → 照 Go1 的 XML 补 gyro/velocimeter/accelerometer/framezaxis/subtreeangmom + imu site
3. **脚部 site 缺失**：foot_height_scan 需要 4 个脚 site → 在 calf body 添加 FR/FL/RR/RL site
4. **碰撞 geom 无名字**：奖励/终止配置按名字匹配 → 用 ElementTree 批量命名 trunk/hip/thigh/calf 碰撞几何
- 通用经验：**mujoco_menagerie 的模型都不是为 RL 训练的，接入前需要补齐 sensor、site、geom 命名**；Go1 的 mjlab 自带 XML 是现成模板

### A1 训练失败排查（重要！）→ 初始姿态悬空
- 现象：A1 训练 4000 迭代后 track_linear 只有 0.66（且是宽松 σ 的保底值），行为验证 vx≈0（学会站但完全不会走）；Go1 同配置正常行走
- 排查：打印初始 trunk 高度 = **1.598m（悬空自由落体！）**
- 根因：**menagerie a1.xml 的 trunk body 自带 `pos="0 0 0.43"` 偏移**，mjlab 的 `init_state.pos` 是 free joint（trunk 原点）的世界位置——之前误套 legged_gym 的 0.42（legged_gym 的 URDF 无 body 偏移），叠加后机器人悬空 0.57m+，训练时每次都"自由落体→站稳"，学会站但学不会走
- 修复：init_state.pos.z = **0.27**（menagerie home keyframe 官方站姿），joint 角用 keyframe 值（thigh 0.9, calf -1.8）
- 验证：修正后初始 trunk 高度 0.316m（正常站姿）
- 教训：**接入新机器人时，初始姿态必须用模型自带的 keyframe/站姿参数，不能跨模型套用**（legged_gym 的值只对 legged_gym 的 URDF 有效）

### 其它 mjlab 踩坑（续）

### A1 "学不会走" 的完整排查（关键！3 轮迭代实验）
- 现象：A1 在 rough 任务中无论 PD 参数（kp=20/0.5、电机推导 7-16、Go1 同构 16-36）都卡在 track_linear 0.5-0.7 不涨（等于"站着不动"的保底奖励），行为验证 vx≈0；Go1 同任务 2000 迭代到 1.41 正常行走
- 排查过程：
  1. 初始姿态悬空（trunk body pos 0.43 偏移）→ 修复（keyframe z=0.27），仍不走
  2. PD/action scale 三轮对照（v1-v4）→ 全部卡 0.5
  3. env_cfg 全量 diff（Go1 vs A1）→ rewards/observations 完全一致，差异只剩机器人本体
  4. **决定性实验：A1 flat 任务（无 illegal_contact 终止）300 迭代 track_linear 0.72、误差 0.03 → 能学会走！**
- 结论：**rough 任务的 illegal_contact 终止（大腿碰撞地面即终止）是元凶**——A1 的腿比 Go1 短（0.285 vs 0.293m），迈步时大腿更容易碰地触发终止，策略学到"不动最安全"的局部最优；flat 任务没有该终止，策略敢探索迈步
- 教训：① 终止条件比奖励项更能决定"敢不敢探索"；② 接入新机器人时如果学不会任务，先做**任务难度消融**（flat vs rough）；③ 训练指标卡在"不动保底值"是终止条件过严的典型信号
- 后续：flat 长训验证 + rough 配置修改（A1 的 rough 改用 fell_over 终止，不用 illegal_contact）
