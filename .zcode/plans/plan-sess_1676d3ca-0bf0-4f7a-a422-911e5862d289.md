
# ROS 2 + OpenCV + AprilTag 相机位姿系统 — 实施计划

## 目标环境（已核实）
- Ubuntu 22.04 / ROS 2 **Humble** / Python 3.10 / OpenCV 4.5.4
- 摄像头：`/dev/video0`（Acer Integrated RGB），默认 **MJPG 1280×720 @ 30**
- AprilTag：**tag36h11 / ID 0 / 100 mm**
- 棋盘格：**8×6 内角点 / 25 mm**
- 工作区：`~/apriltag_pose_ws`（当前不存在，全新创建；不动 `~/colcon_test`、`~/d2lros2`、`~/k230_setup`、`~/桌面/robocon`）
- ROS 发行版通过 `$ROS_DISTRO` 引用，不硬编码 `humble`

## 阶段 0 —— 前置准备（可回滚，无破坏性）
1. 验证 apt 网络可达：`sudo apt update`（若失败则中断并汇报，不猜测）。
2. 将当前用户加入 `video` 组（提示需重新登录才完全生效；当前 ACL 已可用）。
3. 创建工作区目录 `~/apriltag_pose_ws/src` 与 `~/apriltag_pose_ws/data/distance_results`。

## 阶段 2 —— 摄像头探测 & 手工验证
- 编写 `scripts/probe_camera.sh`：枚举 `/dev/video*`、用 `v4l2-ctl` 输出各节点的格式，剔除无格式/GREY 节点，推荐 `/dev/video0`。
- 用 `ffplay -f v4l2 -input_format mjpeg -video_size 1280x720 /dev/video0` 或 `cheese` 目视确认能出彩色图像。
- 成功标准：能看到摄像头画面。

## 阶段 4 —— `camera.launch.py`（v4l2_camera）
- 参数：`video_device`(默认 `/dev/video0`)、`image_width=1280`、`image_height=720`、`frame_rate=30`、`pixel_format=mjpeg2rgb`（v4l2_camera 支持解码 MJPEG）、`camera_frame_id=camera_optical_frame`、`camera_name=integrated_camera`、`camera_info_url`（默认空，允许覆盖）。
- 命名空间统一 `/camera`，输出 `/camera/image_raw`、`/camera/camera_info`。
- 验收：`ros2 topic hz /camera/image_raw` 稳定 ~30 Hz；`rqt_image_view` 能看画面。

## 阶段 5 —— 相机标定
- `scripts/run_calibration.sh` 与 `launch/calibration.launch.py`，默认 `size=8x6, square=0.025`，`ros2 run camera_calibration cameracalibrator --size 8x6 --square 0.025 --ros-args -r image:=/camera/image_raw -r camera:=/camera`。
- 标定分辨率与运行分辨率一致（1280×720）。
- 完成后我会把生成的 `.yaml` 从 `/tmp` 拷到 `config/camera_info.yaml`（不伪造）。当前只交付 `camera_info.yaml.example`，并在 README 提示：**未标定前不得声称距离精确**。
- launch 用 `file://` URL + `Path.home()`/`get_package_share_directory` 组装路径。

## 阶段 6 —— 图像去畸变
- 在 `full_system.launch.py` 中启动 `image_proc`（`ComposableNodeContainer` 或纯 node 形式，取 Humble 实际支持的形式）。
- 目标话题 `/camera/image_rect`；若 Humble 实际发布的是 `image_rect_color`，在 launch 里 remap 到 `/camera/image_rect`，让下游一致。
- **严格遵守**：`image_rect` + `P[:3,:3]` + 零畸变；`image_raw` + `K` + 真实 `D`。不重复施加畸变。

## 阶段 7 —— AprilTag 检测
- 先在实施时运行 `ros2 pkg prefix apriltag_ros`、`ros2 run apriltag_ros apriltag_node --ros-args --help`、`ros2 interface show apriltag_msgs/msg/AprilTagDetection[Array]`，按实际参数名与字段名写 `config/tags.yaml`。
- 计划中的 tags.yaml 骨架（family=`36h11`、id=`0`、size=`0.100`、frame=`tag_0`、`max_hamming`、`decimate`、`nthreads`、`refine_edges`、`pose_estimation_method`），最终字段名以运行时 `--help` 输出为准。
- Remap 检测节点输入到 `/camera/image_rect` 和 `/camera/camera_info`。
- 验收：`ros2 topic echo /detections` 有内容；`ros2 run tf2_ros tf2_echo camera_optical_frame tag_0` 有 TF（若 apriltag_ros 未自动发 TF，由 visualizer 补发，先 `ros2 topic echo /tf` 判断避免重复）。

## 阶段 8 —— `visualizer_node.py`
- 参数：`image_topic`、`camera_info_topic`、`detections_topic`、`output_image_topic`、`tag_size`、`axis_length`、`use_rectified_image`、`publish_debug_text`。
- 订阅（`ApproximateTimeSynchronizer` 同步 image+detections，CameraInfo 缓存最新有效值）。
- 位姿：`cv2.solvePnP` with `SOLVEPNP_IPPE_SQUARE`，失败回退 `SOLVEPNP_ITERATIVE`（打 warning）。3D 角点按标签中心为原点、按 apriltag_msgs 实际角点顺序**运行时验证并排序**（若消息顺序与 IPPE_SQUARE 要求不符则在代码里重排，并在 README 明确记录最终顺序）。
- 相机矩阵按 `use_rectified_image` 分支：rect→`P[:3,:3]`+零 D；raw→`K`+`D`。
- 图像绘制：4 边、4 角点+编号、中心、ID、tx/ty/tz、`distance = √(tx²+ty²+tz²)`、`cv2.drawFrameAxes` 三维坐标轴。
- 发布到 `/apriltag/image_annotated`。
- TF：仅在 apriltag_ros 未发 `camera_optical_frame→tag_0` 时才发；启动时探测一次 `/tf`。

## 阶段 9 —— `distance_logger_node.py`
- 参数：`camera_frame`、`tag_frame`、`true_distance_m`、`sample_count=100`、`output_directory=~/apriltag_pose_ws/data/distance_results`、`measurement_name`、`lookup_timeout`。
- 用 `tf2_ros.Buffer.lookup_transform` 每帧取 tx/ty/tz，计算 estimated/abs_error/rel_error。
- 100 帧后写 CSV：`tag{id}_true_{mm}mm_YYYYMMDD_HHMMSS.csv`，列 = `timestamp, tx_m, ty_m, tz_m, estimated_distance_m, true_distance_m, absolute_error_m, relative_error_percent`。
- 终端打印均值/中位数/min/max/std/MAE/平均相对误差/RMSE，然后 `rclpy.shutdown()`。
- TF 缺失时不崩溃，限频提示。

## 阶段 10 —— `system_diagnostics_node.py` + `verify_system.sh`
- 脚本检查话题存在性、频率、CameraInfo 有效性（K 非零）、TF 存在、tag_size>0、frame_id 匹配；输出 `[PASS]/[WARNING]/[FAIL]` 与最终 "系统是否达到演示条件"。

## 阶段 11 —— `full_system.launch.py`
- 参数：`video_device, image_width, image_height, frame_rate, camera_info_file, tag_family, tag_id, tag_size, camera_frame, tag_frame, axis_length, use_rviz, enable_distance_logger, true_distance_m, sample_count`。
- 内部启动：v4l2_camera → image_proc（rectify）→ apriltag_ros → visualizer_node → (可选) rviz2 → (可选) distance_logger_node。
- 路径用 `Path.home()` / `get_package_share_directory` / `LaunchConfiguration`；`file://` URL 拼接安全。

## 阶段 12 —— RViz2 配置
- `rviz/apriltag_pose.rviz`：Fixed Frame=`camera_optical_frame`；面板含 TF、Image(`/apriltag/image_annotated`)、Camera（rect + camera_info）、Grid、Axes。

## 阶段 13 —— 单元测试
- `test/test_pose_math.py`：距离公式、abs/rel 误差、RMSE、tag 3D 角点尺寸、`tag_size≤0` 抛异常、CameraInfo K 全零时拒绝求解。
- `test/test_distance_statistics.py`：mean/median/std/MAE/RMSE 数值正确。
- 运行 `colcon test --packages-select apriltag_camera_pose && colcon test-result --verbose`。

## 需要你物理配合的动作（会明确暂停等待）
1. **加入 video 组后重新登录**（可选，不阻塞）。
2. **打印 tag36h11 ID=0 边长 100 mm**，贴在硬板上，卡尺量出实际边长填入 launch 参数。
3. **用 8×6 / 25 mm 棋盘格完成一次相机标定**（1280×720），然后把 `.yaml` 放到 `config/camera_info.yaml`。
4. **测距实验**：分别在 300/500/700/1000/1200 mm 处运行 `collect_distance_data.sh <米>`，采 100 帧生成 CSV。
5. 若焦距/分辨率变了，需重新标定。
